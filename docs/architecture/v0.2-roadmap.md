# v0.2 Roadmap

状态：`draft`

## 1. Purpose

v0.2 的目标不是做完整产品，而是从 v0.1 developer demo 走向更可交互、更可验证的 runtime slice。

当前 v0.1 已证明 kernel loop 可以本地闭环：canonical events、policy-gated execution、artifact provenance、projector replay、checkpoint-assisted rebuild 和 memory boundary read model 都已有最小展示路径。v0.2 应优先降低理解和交互成本，再逐步暴露更接近 runtime 的 server-facing surface。

## 3. Candidate Tracks

### Track A: HTTP API Minimal Surface

状态：`effectively complete / closed for now`

目标：让 demo 从 in-process facade 走向最小 server-facing API。

设计入口：`http-api-minimal-surface-v0.2.md`

当前 slices 已实现为 in-process `HttpApiApp` / `create_http_app(...)`：

- create session
- create run
- submit input
- run one Agent loop step
- get run state
- get Agent loop run control summary
- list events
- get artifact summary
- health check

当前实现不监听端口，不引入 FastAPI / Flask / 新依赖。状态变更仍委托现有 `InProcessServer` / action chain，artifact summary 只返回 canonical `artifact.created` event 中的 summary / ref / provenance。Agent loop run control route 只返回 summary-only control read model，展示 phase / blockers / pending approvals / next actions / progress / deferred capabilities。Agent loop step route 只允许执行当前 control `next_actions` 内的一个 step，并返回更新后的 control；它不自动循环、不调 scheduler、不接 real LLM。request validation 已覆盖 malformed body、method mismatch、unknown session / run / artifact，并要求错误请求不产生 event / action / artifact side effect。response contract 已固定 `status_code`、JSON-compatible body、stable error shape，并通过 HTTP facade demo smoke 覆盖完整 happy path。duplicate-submit boundary 已用 per-app in-memory `idempotency_key` cache 覆盖，不进入 canonical event log，也不是 distributed idempotency。route inventory 已通过 `list_routes()` / `GET /routes` 固定 supported routes；deferred memory query、external ingestion、SSE / stream、approval product / collection API 和 full artifact content routes 返回 stable `501 not_enabled`，且不产生 side effects。Track E 已另行提供 minimal in-process approval resolve route。

Track A 当前关闭在 minimal in-process facade boundary。real listening HTTP server、ASGI / WSGI framework、auth、SSE 和 hosted deployment 只有在显式 reopen Track A 时才进入下一份 design / red tests。

明确不包含：

- auth
- streaming / SSE
- multi-user
- hosted deployment
- real listening HTTP server
- memory query API
- external ingestion API
- full artifact content API

### Track E: Minimal Approval Pause / Resume Boundary

状态：`effectively complete / closed for now`

目标：把现有 pending approval boundary 推进到最小 approve / deny / resume contract。

设计入口：`approval-pause-resume-boundary-v0.2.md`

- `ImportedSnapshot` slice model。
- `InProcessServer.import_external_snapshot(...)` structured helper。

- projection into external observation only。
- quality / confidence / coverage / freshness metadata。
- native canonical state priority over imported observation。
- conflict marking for conflicting snapshots。
- projector does not read raw artifact content。

External observation read-model invariant slice 已完成：

- `RunState.external_observations` has a stable read-model shape with snapshot id, type, source, freshness, quality, provenance, basis refs, status, and conflict metadata。
- checkpoint state includes `external_observations`。

明确不包含：

- real provider integration
- automatic reconciliation
- external source as truth

## 4. Recommended Order

建议优先级：

1. Closed prerequisite: demo/docs polish from the earlier Track D / current Track H area
2. Closed prerequisite: Track A HTTP API Minimal Surface
3. Closed prerequisite: Track C Artifact Content Read Policy / Controlled Full-Content Retrieval
4. Closed prerequisite: Track E Minimal Approval Pause / Resume Boundary
5. Completed demo scenario and acceptance: Track H v0.2 Demo Scenario Expansion
6. Completed demo tag: `v0.2-demo` lightweight tag
7. Closed prerequisite: Track F External Ingestion / ImportedSnapshot
8. Closed stabilization slice: Retry / Cancel / Supersede boundary
9. Later: Track G Memory Query Engine / Tiny Read-Only Query Slice
10. Last / only if explicitly reopened: Track B Real HTTP Adapter / Network Wrapper

理由：

- v0.1 刚闭环，先降低理解成本。
- HTTP API 能把 runtime 边界暴露出来。
- controlled artifact content retrieval 能把 demo 从 summary-only 推进到可验证的 authorized read，而不引入 network / LLM / memory storage。
- ingestion 是 Isotope 区别于普通 tool runner 的关键；Track F boundary / read-model invariants 已锁住 raw external input 不能直接推进 state、`ImportedSnapshot` 不能成为第二事实源、projector 只消费 canonical events 且 imported observation 只能进入 `external_observations`，并且 checkpoint-assisted rebuild 可恢复 external observation read model。该 track 当前 closed for now，不默认继续做 provider adapter / webhook / HTTP ingestion API。
- approval resume 有明显 demo 价值，并能检验 pending state、human gate、resume lifecycle、idempotency 和 grants enforcement；Track C closure 后适合作为下一默认 track。
- explicit v0.2 demo scenario 已展示 Track A / C / E；下一步可以转向新的 kernel boundary，而不是继续扩 demo scope。
- memory query / storage 风险较高，容易过早牵出 ranking / query / promotion。
- real HTTP adapter 对 kernel contract 的新增价值低，且最容易制造 product-readiness 误解。
