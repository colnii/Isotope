# v0.2 Roadmap

状态：`draft`

## 1. Purpose

v0.2 的目标不是做完整产品，而是从 v0.1 developer demo 走向更可交互、更可验证的 runtime slice。

当前 v0.1 已证明 kernel loop 可以本地闭环：canonical events、policy-gated execution、artifact provenance、projector replay、checkpoint-assisted rebuild 和 memory boundary read model 都已有最小展示路径。v0.2 应优先降低理解和交互成本，再逐步暴露更接近 runtime 的 server-facing surface。

## 3. Candidate Tracks

### Track A: HTTP API Minimal Surface

状态：`surface and request validation slices implemented`

目标：让 demo 从 in-process facade 走向最小 server-facing API。

设计入口：`docs/http-api-minimal-surface-v0.2.md`

当前前两批 slice 已实现为 in-process `HttpApiApp` / `create_http_app(...)`：

- create session
- create run
- submit input
- get run state
- list events
- get artifact summary
- health check

当前实现不监听端口，不引入 FastAPI / Flask / 新依赖。状态变更仍委托现有 `InProcessServer` / action chain，artifact summary 只返回 canonical `artifact.created` event 中的 summary / ref / provenance。request validation 已覆盖 malformed body、method mismatch、unknown session / run / artifact，并要求错误请求不产生 event / action / artifact side effect。

明确不包含：

- auth
- streaming / SSE
- multi-user
- hosted deployment
- real listening HTTP server
- memory query API
- external ingestion API
- full artifact content API

### Track B: External Ingestion / ImportedSnapshot

目标：实现外部输入不能直接推进 state 的 ingestion boundary。

可能包含：

- raw artifact capture
- adapter-normalized imported snapshot
- `snapshot.imported` canonical event
- projection into external observation only
- quality / confidence / coverage metadata

明确不包含：

- real provider integration
- automatic reconciliation
- external source as truth

### Track C: Real Memory Storage Slice

目标：从 not-enabled memory boundary 走向最小 file-backed memory storage。

可能包含：

- `FileMemoryStore`
- authorized `write_memory` success path
- `memory.record_created` emission
- summary / ref query only

明确不包含：

- embedding / ranking
- full controlled expand
- session promotion policy
- semantic search

### Track D: Demo / Docs Polish

状态：`effectively complete / closed for now`

目标：让外部读者更容易理解 v0.1 demo。

已完成：

- README quick start / demo command / limitations links
- architecture diagram: `docs/demo-architecture-v0.1.md`
- demo output walkthrough: `docs/demo-walkthrough-v0.1.md`
- v0.1 demo acceptance: `docs/v0.1-demo-acceptance.md`
- "what this proves" / non-goals section
- troubleshooting guide
- CI smoke status

后续仍可以继续做 README presentation polish、screenshots 或 sample JSON，但这些 polish 不再阻塞 v0.2 implementation。

## 4. Recommended Order

建议优先级：

1. Track D: Demo / Docs Polish
2. Track A: HTTP API Minimal Surface
3. Track B: External Ingestion / ImportedSnapshot
4. Track C: Real Memory Storage Slice

理由：

- v0.1 刚闭环，先降低理解成本。
- HTTP API 能把 runtime 边界暴露出来。
- ingestion 是 Isotope 区别于普通 tool runner 的关键。
- real memory storage 风险较高，容易过早牵出 ranking / query / promotion。

## 5. Proposed v0.2 Acceptance Criteria

v0.2 可以被接受，当：

- README 能让新读者在 5 分钟内跑通 demo。
- 有一张 architecture diagram 或 flow diagram 说明 kernel loop。
- 最小 in-process HTTP API boundary 或等价 server-facing surface 可跑通。
- event log / projector / checkpoint 边界仍保持。
- no `x_agent.*` imports。
- CI 仍通过。
- deferred capabilities 继续显式标注。

## 6. Non-Goals

- production release
- real LLM agent
- UI
- hosted service
- multi-tenant
- real semantic memory
- plugin marketplace
