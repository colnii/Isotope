# v0.2 Roadmap

状态：`draft`

## 1. Purpose

v0.2 的目标不是做完整产品，而是从 v0.1 developer demo 走向更可交互、更可验证的 runtime slice。

当前 v0.1 已证明 kernel loop 可以本地闭环：canonical events、policy-gated execution、artifact provenance、projector replay、checkpoint-assisted rebuild 和 memory boundary read model 都已有最小展示路径。v0.2 应优先降低理解和交互成本，再逐步暴露更接近 runtime 的 server-facing surface。

## 3. Candidate Tracks

### Track A: HTTP API Minimal Surface

状态：`effectively complete / closed for now`

目标：让 demo 从 in-process facade 走向最小 server-facing API。

设计入口：`docs/http-api-minimal-surface-v0.2.md`

当前 slices 已实现为 in-process `HttpApiApp` / `create_http_app(...)`：

- create session
- create run
- submit input
- get run state
- list events
- get artifact summary
- health check

当前实现不监听端口，不引入 FastAPI / Flask / 新依赖。状态变更仍委托现有 `InProcessServer` / action chain，artifact summary 只返回 canonical `artifact.created` event 中的 summary / ref / provenance。request validation 已覆盖 malformed body、method mismatch、unknown session / run / artifact，并要求错误请求不产生 event / action / artifact side effect。response contract 已固定 `status_code`、JSON-compatible body、stable error shape，并通过 HTTP facade demo smoke 覆盖完整 happy path。duplicate-submit boundary 已用 per-app in-memory `idempotency_key` cache 覆盖，不进入 canonical event log，也不是 distributed idempotency。route inventory 已通过 `list_routes()` / `GET /routes` 固定 supported routes；deferred memory query、external ingestion、SSE / stream、approval product / collection API 和 full artifact content routes 返回 stable `501 not_enabled`，且不产生 side effects。Track E 已另行提供 minimal in-process approval resolve route。

Track A 当前关闭在 minimal in-process facade boundary。real listening HTTP server、ASGI / WSGI framework、auth、SSE 和 hosted deployment 只有在显式 reopen Track A 时才进入下一份 design / red tests。

明确不包含：

- auth
- streaming / SSE
- multi-user
- hosted deployment
- real listening HTTP server
- memory query API
- external ingestion API
- full artifact content API

### Track B: Real HTTP Adapter / Network Wrapper

状态：`deferred unless Track A is explicitly reopened`

目标：把 in-process HTTP facade 包成真实监听端口或 framework-backed server。

当前不推荐作为下一 track。Track A 已证明 server-facing API shape，real server 会引入 process lifecycle、ports、framework selection、timeouts、logging/security defaults 和 deployment expectations，容易让 v0.2 demo 被误读为 hosted product。

### Track C: Artifact Content Read Policy / Controlled Full-Content Retrieval

状态：`effectively complete / closed for now`

目标：在不改变 projector / checkpoint / event-log truth 的前提下，定义 artifact full content 何时可以被显式授权读取。

设计入口：`docs/artifact-content-read-policy-v0.2.md`

当前已实现到 closed-for-now scope：

- artifact summary remains default。
- explicit grants for full-content retrieval。
- structured `ResourceRef` required。
- no implicit full-content read in projector / checkpoint / HTTP summary endpoint。
- in-process retrieval boundary first, not real network API。
- caller context / purpose required for full-content retrieval。
- unauthorized full-content retrieval fails closed before content read。
- authorized full-content retrieval returns content through `RetrievalService.get_artifact_content(...)`。
- HTTP full-content route has explicit `allow_artifact_content=False` enablement guard。
- HTTP full-content route remains `501 not_enabled` by default and with no retrieval wiring。

明确不包含：

- public hosted content API
- auth / multi-user
- broad retrieval policy engine
- real provider adapter / external ingestion API
- memory controlled expand
- real HTTP server

### Track E: Minimal Approval Pause / Resume Boundary

状态：`effectively complete / closed for now`

目标：把现有 pending approval boundary 推进到最小 approve / deny / resume contract。

设计入口：`docs/approval-pause-resume-boundary-v0.2.md`

当前已有 `approval.requested` event、`approval.resolved` event、pending / resolved projection 和 minimal in-process HTTP resolve route。Track C closure 后，mid-cycle review 选择 Track E 作为下一默认 track；该 track 当前已执行到 closed-for-now scope。

当前 green slices 已实现 minimal scope：pending approval 可 resolve；approved resolution 会 append canonical `approval.resolved`，然后通过现有 executor boundary resume；approved resume 使用原 `PolicyDecision.grants`，不会使用 resolution body 中的 forged grants；denied resolution 会 append `approval.resolved`，但不创建 execution / artifact；duplicate resolution 是受控 conflict；`RunState.approvals` 与 HTTP run read model 能表达 pending / approved / denied approval summary；event-log replay 和 checkpoint-assisted rebuild 可恢复 approval read model；HTTP facade 有 in-process approval resolve route。

仍明确不包含 approval UI、auth / identity、notification、timeout scheduler、complex approval policy DSL 或 real HTTP network server。

### Track F: External Ingestion / ImportedSnapshot

状态：`effectively complete / closed for now`

目标：实现外部输入不能直接推进 state 的 ingestion boundary。

设计入口：`docs/external-ingestion-boundary-v0.2.md`

当前 boundary green slice 已包含：

- `ingestion.py` boundary。
- `ImportedSnapshot` slice model。
- `snapshot.imported` canonical event projection into `RunState.external_observations`。
- projection into external observation only。
- quality / confidence / coverage / freshness metadata。
- native canonical state priority over imported observation。
- conflict marking for conflicting snapshots。
- projector does not read raw artifact content。

External observation read-model invariant slice 已完成：

- `RunState.external_observations` has a stable read-model shape with snapshot id, type, source, freshness, quality, provenance, basis refs, status, and conflict metadata。
- checkpoint state includes `external_observations`。
- checkpoint-assisted rebuild restores the same external observation read model as event-log replay。
- duplicate snapshot identity is controlled。
- conflicts preserve basis refs and do not become native deterministic facts。
- imported observations still do not overwrite native `RunState.status` or action status。

明确不包含：

- real provider integration
- automatic reconciliation
- external source as truth

当前关闭在 boundary / projection / read-model / checkpoint scope。v0.2 不实现真实 provider adapter、OpenAI / Responses integration、GitHub webhook、external ingestion HTTP API 或 hosted listener；HTTP `/external-ingestion` 仍 `501 not_enabled`，`server.ingest_external_input(...)` 仍 fail-closed / `not_enabled`。后续只有显式 reopen Track F 并新增设计 / red tests 时，才进入 provider adapter、webhook、HTTP ingestion API 或 reconciliation boundary。

### Track G: Memory Query Engine / Tiny Read-Only Query Slice

## 4. Recommended Order

建议优先级：

1. Closed prerequisite: demo/docs polish from the earlier Track D / current Track H area
2. Closed prerequisite: Track A HTTP API Minimal Surface
3. Closed prerequisite: Track C Artifact Content Read Policy / Controlled Full-Content Retrieval
4. Closed prerequisite: Track E Minimal Approval Pause / Resume Boundary
5. Completed demo scenario and acceptance: Track H v0.2 Demo Scenario Expansion
6. Completed demo tag: `v0.2-demo` lightweight tag
7. Closed prerequisite: Track F External Ingestion / ImportedSnapshot
8. Closed stabilization slice: Retry / Cancel / Supersede boundary
9. Later: Track G Memory Query Engine / Tiny Read-Only Query Slice
10. Last / only if explicitly reopened: Track B Real HTTP Adapter / Network Wrapper

理由：

- v0.1 刚闭环，先降低理解成本。
- HTTP API 能把 runtime 边界暴露出来。
- controlled artifact content retrieval 能把 demo 从 summary-only 推进到可验证的 authorized read，而不引入 network / LLM / memory storage。
- ingestion 是 Isotope 区别于普通 tool runner 的关键；Track F boundary / read-model invariants 已锁住 raw external input 不能直接推进 state、`ImportedSnapshot` 不能成为第二事实源、projector 只消费 canonical events 且 imported observation 只能进入 `external_observations`，并且 checkpoint-assisted rebuild 可恢复 external observation read model。该 track 当前 closed for now，不默认继续做 provider adapter / webhook / HTTP ingestion API。
- approval resume 有明显 demo 价值，并能检验 pending state、human gate、resume lifecycle、idempotency 和 grants enforcement；Track C closure 后适合作为下一默认 track。
- explicit v0.2 demo scenario 已展示 Track A / C / E；下一步可以转向新的 kernel boundary，而不是继续扩 demo scope。
- memory query / storage 风险较高，容易过早牵出 ranking / query / promotion。
- real HTTP adapter 对 kernel contract 的新增价值低，且最容易制造 product-readiness 误解。
