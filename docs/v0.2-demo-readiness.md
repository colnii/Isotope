# v0.2 Demo Readiness

状态：`reviewed`

## 1. Purpose

本文记录当前是否已经足够形成 `v0.2 developer demo`，以及现有 `python -m isotope_kernel.demo` 与 v0.2 已完成 tracks 之间的展示差距。

本文件不是 tag / release 决策，不要求修改 demo command，也不声明项目已经是产品级 runtime。当前 post-tag 状态见 `docs/v0.2-demo-acceptance.md` 和 `docs/current-status.md`。

## 2. Current Demo

当前 demo 命令仍是：

```bash
python -m isotope_kernel.demo
python -m isotope_kernel.demo --json
```

它仍是 deterministic artifact-producing kernel loop，使用临时目录，不调用 real LLM，不启动 real HTTP server，不访问网络，不展示真实 memory storage / query。

该 review 当时的 baseline：`735 passed`。当前 mainline baseline 已随 Track F boundary / read-model / checkpoint slices 更新为 `765 passed`。

## 3. What The Demo Shows

现有 demo 已展示：

- session / run creation。
- deterministic action path。
- `ActionCompiler -> PolicyEngine -> Executor` action chain。
- `PolicyDecision.grants` enforcement on the successful artifact path。
- artifact summary / structured ref / execution provenance。
- canonical event log。
- `RunProjector` read model。
- event-log replay verification。
- checkpoint-assisted rebuild verification。
- memory boundary status: `boundary_only`。

这些已经足够证明 v0.1 kernel loop 和若干核心 v0.2 invariants 没有被破坏。

## 4. Prior Gap

本 review 当时记录：默认 v0.1 demo 尚未展示：

- Track A `HttpApiApp` / `create_http_app(...)` in-process HTTP facade。
- Track C controlled full-content retrieval through structured `ResourceRef` + grants + caller context / purpose。
- Track E approval pause / resolve / approved resume / denied no-execute path。

这些缺口不是 bug。对应能力已经由 dedicated tests 和 docs 锁住；当时的 gap 是 demo output 没有把它们串成一个可见 scenario。

该 gap 已通过 `docs/v0.2-demo-scenario.md` 和 `python -m isotope_kernel.demo --scenario v0.2` 关闭。默认 v0.1 demo 仍保持兼容。

## 5. Readiness Judgment

如果目标是 kernel boundary proof，当前代码和测试已经足够支持 `v0.2 developer demo readiness` 记录：

- Track D / A / C / E 都已 closed for now。
- full regression 在该 review 当时是 `735 passed`；当前 mainline 是 `765 passed`。
- demo plain / JSON 仍可运行。
- CI / packaging smoke 仍覆盖原 demo path。

如果目标是给朋友、外部 reviewer 或新读者看，当前 demo 还不够像 `v0.2 demo`，因为它没有展示 Track A / C / E 的新增可见能力。

## 6. Recommendation

已按本 review 推荐完成一个很小的 `v0.2 demo scenario expansion`。后续已进入 Track F External Ingestion / ImportedSnapshot，并完成第一批 boundary green slice；不要把这解读为 real provider adapter、webhook 或 public ingestion API 已实现。

建议扩展仍保持 in-process、no-network、no-real-LLM、no-new-dependency：

- 通过 `HttpApiApp` 跑同等 happy path，证明 Track A facade。
- 增加一个 controlled artifact content retrieval sample，证明 Track C 只在 authorized retrieval layer 返回 content。
- 增加一个 approval pause / approve / deny mini scenario，证明 Track E pending / resolved read model。
- 保持 default `python -m isotope_kernel.demo` 不输出 full artifact content；如需要，可新增 explicit `--v0.2` 或 internal helper，先走 red tests 再实现。
- 当前 explicit `--scenario v0.2` 已实现，并由 `tests/isotope_kernel/test_demo_v0_2_scenario.py` 覆盖。

如果短期目标不是外部展示，也可以保持当前 demo 不变。Track F boundary doc 已在 `docs/external-ingestion-boundary-v0.2.md`，且第一批 boundary / projection slice 已通过测试；下一步 Track F 只能通过新的 design / red tests 继续。

## 7. Non-Goals

- 本 review 本身不打 tag；当前 `v0.2-demo` tag 状态见 acceptance / current-status。
- 不发布 GitHub Release。
- 不启动 real HTTP server。
- 不引入 FastAPI / Flask / new dependency。
- 不实现 external ingestion。
- 不实现 real LLM。
- 不实现 durable memory storage / query。
