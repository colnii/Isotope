## 快速读法

- `apps/` 是薄入口：CLI/API 只负责接用户输入，再转到 `src/isotope/`。
- `src/isotope/` 是主实现：按 `core`、`features`、`platform`、`llm`、`runtime`、`integrations` 等层次拆分。
- `tests/` 是回归测试根目录：按 `unit`、`integration`、`smoke`、`e2e` 分层覆盖源码边界、功能和行为。
- `docs/current/` 是当前事实入口；`docs/architecture/`、`docs/features/`、`docs/reviews/` 是参考和证据；`docs/archive/` 是历史材料。
- `docs/superpowers/` 保存分支执行计划和规格草稿，不作为 current 入口。

## `src/isotope/` 层级

| 路径 | 当前职责 |
| --- | --- |
| `apps/` | package 内 HTTP/API app facade（门面）实现；根目录 `apps/` 仍是外部薄入口。 |
| `core/` | 产品主流程门面，串起 session、conversation、task、dispatch 和 response。 |
| `features/` | 面向用户或产品能力的功能入口，如 ask、files、projects、research、screen、supervisor、tasks、workbench。 |
| `agents/` | Agent loop、调度、capacity graph、fanout 和 goal queue 等智能体编排能力。 |
| `capabilities/` | capability catalog、runner 和可被能力系统/LLM tool 调用的工具封装。 |
| `execution/` | action executor、terminal backend、screen backend 等执行边界。 |
| `integrations/` | 外部系统集成，当前主要是 Codex CLI/server/task/session/live smoke。 |
| `interfaces/` | HTTP route、validation、serialization 和 response facade。 |
| `llm/` | LLM provider、tool bridge、pool 和 capacity calling。 |
| `memory/` | 长期记忆、低敏 query read model、memory view 和 worker event 兼容入口。 |
| `platform/` | 事件、schema、状态存储、ledger、projector、registry、errors 和 ids。 |
| `policy/` | 策略和 grant 边界。 |
| `rag/` | 检索增强生成（RAG）的 ingestion / retrieval 原型边界。 |
| `runtime/` | in-process server、action 提交/审批、agent loop handoff、workspace helper 和 checkpoint。 |
| `workspace/` | artifact 捕获和工作区资源能力。 |

## 常用真实清单命令

```bash
# tracked 文件数
git -c core.quotePath=false ls-files | wc -l

# tracked 目录数，包含根目录
git -c core.quotePath=false ls-files \
  | awk 'BEGIN{print "."} {n=split($0,a,"/"); p=""; for(i=1;i<n;i++){p=(p?p"/":"")a[i]; print p}}' \
  | sort -u \
  | wc -l

# 顶层 tracked 文件分布
git -c core.quotePath=false ls-files | cut -d/ -f1 | sort | uniq -c

# 查看某个目录的真实当前文件
git -c core.quotePath=false ls-files src/isotope/features/supervisor
```
